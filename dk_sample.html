Topic 4.2 · Binary Heap: Array Architecture & Sift-Up

Core Syllabus: [4.1.2] [4.2.1] [4.2.4]
01 Mechanical Intuition & Visual Architecture
Memory Bottleneck: Explicit Pointer Trees

Dynamic nodes store two 8-byte child pointers (*left, *right).

For N keys, 16N bytes are wasted; non-contiguous allocations cause continuous CPU cache misses.

The DK Breakthrough: Contiguous Complete Tree

Enforcing a Complete Binary Tree shape eliminates all pointer overhead.

Parent-child links map purely to integer arithmetic inside an array with optimal cache locality.

Figure 4.2.1 · Spatial Architecture
Complete Binary Tree to Array Index Mapping
  • Logical Completeness: Tree levels are packed strictly left-to-right without internal gaps, guaranteeing contiguous array indices 0 to N - 1.
  • Zero-Pointer Arithmetic: Given current node i, the parent index is ⌊(i - 1) / 2⌋, while left child is 2i + 1 and right child is 2i + 2.
  • Examiner Criterion: Look at the curved grey leader lines connecting indices—random access eliminates O(N) list traversals.
Figure 4.2.2 · Dynamic State Machine
Up-Heap (Sift-Up) Execution along Ancestor Path
  • Tail Placement: New key 7 is first placed at the heap boundary (index 11), preserving the structural shape invariant.
  • Ancestor Tube Isolation: Notice the shaded grey tube—only direct ancestors on the root path are compared. Unrelated subtrees remain untouched.
  • Local Invariant Restoration: Key 7 > Parent 6 violates Max-Heap order; swapping them propagates the key upward in strictly O(log N) time.

Topic 4.2 · Exam Combat, Trace Protocol & Traps

Combat Anatomy: [02] [03] [04]
02 English Computational Thinking & Answer Templates
Template 1 · Invariant Preservation Causal Chain (Insert / Up-Heap)

Inserting element X appends it to index N, strictly preserving the Structural Completeness Invariant.

Because X may exceed its parent at index ⌊(i - 1) / 2⌋, the Heap-Order Invariant may be locally violated.

The algorithm iteratively swaps X with its parent along the ancestor path until A[parent] ≥ X or root is reached.

Template 2 · Logarithmic Time Complexity Justification

The maximum number of comparisons and swaps is bounded by tree height h = ⌊log2 N⌋.

Because each ancestor level performs exactly one comparison, insertion executes in strictly O(log N) worst-case time.

04 Lethal Exam Traps & Answer Optimization Matrix
❌ Vague Answer (0 ~ 1 Mark) ✅ Full-Mark Criterion Answer (Full Marks)
Q: Why is an array preferred over a linked list for binary heaps?
"Arrays are faster and easier to implement in C."
[Examiner note: 0 Marks. Lacks mechanical cause: fails to contrast O(1) index arithmetic against O(N) traversal.] 		Criterion Answer:
A complete binary tree in an array computes parent and child addresses in O(1) arithmetic time (⌊(i-1)/2⌋, 2i+1). A linked tree lacks random access, requiring O(N) sequential traversal to locate the insertion tail or parent, degrading insertion from O(log N) to O(N).
Q: What is the maximum number of comparisons to insert into a heap of size N?
"Approximately log N comparisons."
[Examiner note: Inexact boundary. Does not credit full floor formula.] 		Criterion Answer:
At most ⌊log2 N⌋ comparisons, because up-heap traverses a single ancestor path performing exactly 1 comparison per level.
⚠️ CRITICAL EXAM PITFALL: 0-BASED VS 1-BASED INDEX SHIFT

Check the root index immediately! In 0-based arrays (Figure 4.2.1 above), Parent = ⌊(i - 1) / 2⌋. In 1-based arrays, Parent = ⌊i / 2⌋. Mixing up the two formulas is the #1 reason students lose 100% of tracing marks in COMP20003 exams.
