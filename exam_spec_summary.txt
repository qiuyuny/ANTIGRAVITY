[2.0] Asymptotic Complexity & Recurrences
Index & Concept
Mathematical Definition / Closed-Form Formula
Result / Exam Rule
[2.1.1] Big-O (Upper Bound)
f(n) in O(g(n)) iff there exists c > 0, n0 >= 1 : for all n >= n0, 0
<= f(n) <= c * g(n)
Asymptotic upper bound (<=)
[2.1.1] Big-Omega (Lower
Bound)
f(n) in Omega(g(n)) iff there exists c > 0, n0 >= 1 : for all n >=
n0, f(n) >= c * g(n) >= 0
Asymptotic lower bound (>=)
[2.1.1] Big-Theta (Tight Bound)
f(n) in Theta(g(n)) iff f(n) in O(g(n)) AND f(n) in Omega(g(n))
Exact asymptotic growth rate (==)
[2.1.2] Growth Hierarchy
O(1) < O(log n) < O(sqrtn) < O(n) < O(n log n) < O(n^2) <
O(n^3) < O(2^n) < O(n!)
Log base change is constant: log2n =
Theta(log10n)
[2.2.1] Arithmetic Series
sum(i=1 to n) i = 1 + 2 + 3 + ... + n = n(n + 1) / 2
Nested loop (i++; j < i) -> Theta(n^2)
[2.2.2] Geometric Series
sum(k=0 to m) r^k = (r^(m+1) - 1) / (r - 1) [For r=2: 2^(m+1)
- 1]
Outer i *= 2, inner j < i: 1+2+4+...+2^m <
2n -> Theta(n)
[2.2.2] Harmonic / Log Sum
sum(i=1 to n) (1/i) = Theta(log n) | sum(i=1 to n) log(i) =
log(n!) = Theta(n log n)
Outer i *= 2 (alone) runs floor(log2 n) + 1
times -> Theta(log n)
[2.3.3] Master Theorem
T(n) = a T(n/b) + Theta(n^d)
Compare d with log_b(a) (or compare b^d with a):
• Case 1: d > log_b(a) [a < b^d] -> T(n) = Theta(n^d)
• Case 2: d = log_b(a) [a = b^d] -> T(n) = Theta(n^d log n)
• Case 3: d < log_b(a) [a > b^d] -> T(n) = Theta(n^(log_b a))
Examples:
• Binary Search: T(n) = T(n/2) + O(1) ->
a=1,b=2,d=0 -> Theta(log n)
• Mergesort: T(n) = 2T(n/2) + Theta(n) ->
a=2,b=2,d=1 -> Theta(n log n)
• 3-Split O(1): T(n) = 3T(n/2) + O(1) ->
Theta(n^(log2 3))

[4.2.1] Heap Invariants
1. Shape: Complete Binary Tree (filled left-to-right)
2. Order: Max-Heap A[Parent] >= A[i] | Min-Heap A[Parent] <=
A[i]
Root at index 1 is always global max
(Max-Heap) or min (Min-Heap)
[4.2.2] 1-Based Array Math
Root = 1 | Parent(i) = floor(i / 2) | Left(i) = 2i | Right(i) = 2i + 1
Leaves are at indices floor(n/2) + 1 ... n |
Last internal node = floor(n/2)
[4.2.3] Why Array > Linked List
Array computes parent/child indices in O(1) arithmetic
Linked list lacks random access -> finding
parent/last node takes O(n), ruining
O(log n) heap ops
[4.2.4] Insertion (upheap)
Place new key at A[n+1]; swap with Parent(i) while heap order
violated
Worst-case: O(log n) swaps/comparisons
along root path
[4.2.4] Deletion (downheap)
Save A[1]; move A[n] to A[1]; n--; swap with higher-priority
child
Worst-case: O(log n) swaps/comparisons
(2 comparisons per level)
[4.3.1] Top-Down Build
Insert n items one-by-one into empty heap using upheap
Worst-case Time: O(n log n)
[4.3.2] Bottom-Up Heapify
Put n items in array; for i = floor(n/2) down to 1: downheap(i)
Tight Worst-Case Time: Theta(n)
(performs n/2 downheaps)
[4.3.3] m-th Smallest (m << n)
• Method A (Full Sort): Sort array + index m -> O(n log n)
• Method B (Partial Heapsort): Bottom-up Min-Heap Theta(n) +
m × delete-min -> O(n + m log n)
• Method C (Size-m Max-Heap): Build size-m Max-Heap
Theta(m) + scan n-m items (if < root, replace & downheap) ->
O(n log m)
When m << n, Methods B & C beat O(n
log n)

[5.1] Fundamentals
h(k) = k mod M | Load Factor alpha = n / M
Choose M = Prime to distribute keys evenly when inputs share

[5.2.1] Separate Chaining
Slot h(k) points to a Linked List of keys
• alpha can exceed 1.0
• Avg Search: O(1 + alpha) | Worst Search (all n keys collide in 1
list): O(n)
[5.2.2] Linear Probing
h_i(k) = (h(k) + i) mod M for i = 0, 1, 2, ...
• Requires alpha <= 1 (degrades severely when alpha > 0.7)
• Probe Count: Count EVERY checked slot from home slot until
match or empty slot
• Suffers from Primary Clustering (adjacent occupied slots
merge into long blocks)

[5.2.3] Double Hashing
h_i(k) = (h1(k) + i * h2(k)) mod M
• Eliminates primary clustering; setting h2(k) = 1 reduces to
Linear Probing
• TWO MANDATORY RULES for h2(k):
1. h2(k) ≠ 0 for all k (otherwise infinite loop on same slot)
2. gcd(h2(k), M) == 1 (h2(k) and table size M must be coprime
so all M slots are reachable)
[5.2.4] Quadratic Probing
h_i(k) = (h(k) + i^2) mod M
Avoids primary clustering, but keys with same h(k) follow
identical path (Secondary Clustering)

[6.1.1] Core Jargon
• Stable: Equal elements preserve their original relative order • In-place: O(1) extra data structure space •
Adaptive: Faster on pre-sorted input
[6.3.1] Hoare's Partition
(Quicksort Trace)
1. Pick leftmost element as pivot p = A[lo]. Set pointers L = lo + 1, R = hi.
2. Creep L right while A[L] < p. Creep R left while A[R] >= p.
3. If L < R (both stopped on an inversion), swap(A[L], A[R]) and repeat Step 2.
4. When pointers cross (L >= R), stop and swap pivot A[lo] with boundary pointer. Partition takes Theta(n)
time.
[6.3.3] Quicksort Pivot
Improvements
• Problem: Fixed leftmost/rightmost pivot on already-sorted (or reverse-sorted) input creates 0 / (n-1) splits
-> Worst-case Theta(n^2).
• Fix 1 (Randomized Pivot) & Fix 2 (Median-of-Three: median of first, middle, last): Eliminates predictable bad
inputs; expected time O(n log n).
• Exam Q: Does random pivot change worst-case time complexity? NO — unlucky random choices still give
O(n^2) theoretical worst case.
[6.3.4] Quicksort + Insertion
Sort Hybrid Cutoff
• Optimization: Stop Quicksort recursion when subarray size <= k (e.g. 10–15), then run one final pass of
Insertion Sort over the whole array.
• Exam Q: Improves real runtime (avoids tiny recursive call overhead + cache friendly), but DOES NOT change
asymptotic Big-O complexity.
[6.4.3] Mergesort Variants
• Top-Down: Recursive split in half. • Bottom-Up: Iterative merge of sizes 1 -> 2 -> 4 -> 8...
• Natural (Adaptive) Mergesort: Identifies existing monotonically increasing runs first; Best-case Theta(n) on
sorted input (fewer comparisons).
[6.5.1] Heapsort Trace
Phase 1: Bottom-up build Max-Heap in Theta(n). Phase 2: Repeat n-1 times: swap root A[1] with last heap
item A[k], k--, downheap(1) in O(n log n).
• Instability Reason: Swapping root A[1] with A[k] jumps equal elements over each other, destroying relative
order.

[7.3.8] All-Pairs Shortest Path: Run |V| ×
Dijkstra vs Floyd-Warshall?
• |V| × Dijkstra takes O(|V|(|E|+|V|) log |V|).

fatness path between any pair of vertices.
2. Fastest Lookup on MST: Since an MST is sparse (|E| = |V| - 1), run Dijkstra / BFS / DFS on the

[6.1.1] Core Jargon
• Stable: Equal elements preserve their original relative order • In-place: O(1) extra data structure space •
Adaptive: Faster on pre-sorted input
[6.3.1] Hoare's Partition
(Quicksort Trace)
1. Pick leftmost element as pivot p = A[lo]. Set pointers L = lo + 1, R = hi.
2. Creep L right while A[L] < p. Creep R left while A[R] >= p.
3. If L < R (both stopped on an inversion), swap(A[L], A[R]) and repeat Step 2.
4. When pointers cross (L >= R), stop and swap pivot A[lo] with boundary pointer. Partition takes Theta(n)
time.
[6.3.3] Quicksort Pivot
Improvements
• Problem: Fixed leftmost/rightmost pivot on already-sorted (or reverse-sorted) input creates 0 / (n-1) splits
-> Worst-case Theta(n^2).
• Fix 1 (Randomized Pivot) & Fix 2 (Median-of-Three: median of first, middle, last): Eliminates predictable bad
inputs; expected time O(n log n).
• Exam Q: Does random pivot change worst-case time complexity? NO — unlucky random choices still give
O(n^2) theoretical worst case.
[6.3.4] Quicksort + Insertion
Sort Hybrid Cutoff
• Optimization: Stop Quicksort recursion when subarray size <= k (e.g. 10–15), then run one final pass of
Insertion Sort over the whole array.
• Exam Q: Improves real runtime (avoids tiny recursive call overhead + cache friendly), but DOES NOT change
asymptotic Big-O complexity.
[6.4.3] Mergesort Variants
• Top-Down: Recursive split in half. • Bottom-Up: Iterative merge of sizes 1 -> 2 -> 4 -> 8...
• Natural (Adaptive) Mergesort: Identifies existing monotonically increasing runs first; Best-case Theta(n) on
sorted input (fewer comparisons).
[6.5.1] Heapsort Trace
Phase 1: Bottom-up build Max-Heap in Theta(n). Phase 2: Repeat n-1 times: swap root A[1] with last heap
item A[k], k--, downheap(1) in O(n log n).
• Instability Reason: Swapping root A[1] with A[k] jumps equal elements over each other, destroying relative
order.
